# 优化器分组与学习率核查

本轮只读取保存的配置、参数形状、三份已留存权重中的优化器分组和当前源码；没有构建或运行模型，也没有进行评价或训练。参数分组按名称正则表达式匹配，并非按层类型自动识别。

## n 配置

N0—N4 保存的设置均使用 AdamW，默认权重衰减为 0.0001，另有名称匹配的零衰减组。骨干网络的两个规则写为 `(?=.*norm|bn)` 和相应否定形式；由于 `norm|bn` 没有用非捕获组括起来，`bn` 分支在名称开头尝试匹配，而不是匹配名称中的任意位置。以 `backbone.stem.stem1.bn.weight` 为例，按所查代码和规则，它进入默认衰减组，而非所配置的骨干零衰减组。N0 和 N4 留存检查点中，对应的骨干零衰减组均为空；保存的参数 ID 本身不能证明其与名称的一一对应。

## s 配置

S1 的规则按名称中的 `bn` 和 `norm` 字符串分组。骨干中名称不含 `bn` 的参数进入配置学习率 0.0002、默认权重衰减 0.0001 的组；其余组的配置学习率为 0.0004。所查实现中，`high_freq_enhance.1`、`high_freq_enhance.4` 和 `spatial_attention.1` 是 BatchNorm 层，但其参数名不含 `bn`，因此按留存分组规则会进入前一组。MSCA-Dilated 的顺序容器中也有这样的 BatchNorm 参数。原稿“除 BatchNorm 以外的骨干参数使用 0.0002”过于宽泛，本轮已改为名称规则描述。

三份 N0、N4、S1 检查点的分组超参数、六组配置及参数名示例的哈希见 `optimizer_groups_audit.json`；BN 顺序容器下标和示例匹配的独立静态核查见 `optimizer_semantic_verification.json`。这些证据支持“所查代码与保存配置组合下”的分组解释，不能认证历史训练时的源码版本，也不能仅凭优化器参数 ID 重建完整的历史名称映射。

## 学习率时序

六组保存配置均选择 flat-cosine、2000 步预热、`lr_gamma=1.0`。所查调度函数在预热结束后的目标值不再衰减。另外，所查训练器仍会构造 500 步 LinearWarmup 对象：它在构造时先将初始学习率缩为基础值的 1/500；之后的优化器更新先于 flat-cosine 调度器更新。因此不能把初始第一步简单描述成从零开始的完整二次曲线。恢复检查点也可能改变恢复后的实际优化器状态。历史代码身份尚未证实，不能将该细节断言为所有历史运行的精确轨迹。

这些发现不会使旧 N0 与 N4 的不同批次训练变成公平对照。原配对训练未完成，后续诊断也不能替代它，稿件尚不能据此宣布达到投稿要求。
