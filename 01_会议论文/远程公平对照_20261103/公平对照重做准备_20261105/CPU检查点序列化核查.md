# CPU 检查点序列化核查

本次以留存的 BASE 零基第 213 轮最佳检查点及其已保存的预测、评价数组和学习率记录为输入，检查准备中的逐轮保存接口能否在 CPU 上写出并用 `weights_only=True` 读回状态。没有构建模型、运行前向、重新评价或更新优化器。

从禁用候选中仅提取随机状态采集和状态字典构造两个函数；用简单的状态字典包装器提供留存张量，不导入或运行候选训练驱动。临时保存后，重新读取的模型与 EMA 张量、优化器及辅助状态与输入一致，EMA 张量哈希也与既有留存记录一致；本轮检查了该轮 1,617 条学习率记录。临时文件已删除，原检查点、预测和评价数组的哈希未改变。

第一次成功检查逐项比较了上述状态和新随机状态；第二次增加了整个测试用状态字典的往返比较，包括测试元数据，结果一致。两个机器报告均保留；初版检查程序的哈希快照为 `check_checkpoint_serialization_before_full_compare.py.txt`。

**随机状态不是历史证据。**序列化时使用的是本次新生成的 CPU 随机状态；CUDA 字段使用 CPU 生成器状态作为占位，没有读取真实 CUDA 随机状态。运行标识及部分控制信息也是测试值。临时输出不能用作原轨迹续训检查点，测试也不能证明真实 GPU 上的随机状态、训练数值或新驱动与旧驱动的运行等价。

首次尝试读取学习率压缩流到文件末尾时，因原中断文件缺少 gzip 结束标记而退出；失败记录见 `cpu_checkpoint_smoketest_initial_failure.txt`。修正后在目标轮的下一轮边界停止读取，并核对目标轮完整的 1,617 条记录；这不意味着压缩文件末尾完整。

机器记录为 `cpu_checkpoint_serialization_smoketest.json` 和 `cpu_checkpoint_serialization_smoketest_v2.json`，程序在 `本地CPU核验_20261103/check_checkpoint_serialization_only.py`。新训练授权请求仍待答复；真实服务器连接、GPU 状态和完整公平对照尚未验证。英文稿未修改，尚不能宣布达到投稿要求。
