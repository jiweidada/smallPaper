并行训练可行性核查（2026-11-04）

用户询问在显存有空余时能否同时训练已授权的 BASE 与 FULL。此核查只读取现有运行状态、预检回执和队列代码；没有启动额外训练、修改固定配置或干预现有进程。

设备与瞬时状态：parallel_gpu_memory_probe.json 记录 1 张 RTX 3090，总显存 24576 MiB，已用 15517 MiB，空闲 8736 MiB（查询时间以该文件修改时间为准，空闲数会变化）。parallel_gpu_process_probe.json 记录当时的 GPU 计算进程。

峰值风险：status_training_18.json 中，BASE 第 5 个人类轮次（actual_loop_epoch=4）训练时，GPU 已用显存观测到 22131 MiB。预检 FULL.json 记录一次前向、反向和预测检查中 PyTorch 的 peak_cuda_allocated_bytes=2747689472，约 2620.4 MiB；预检没有 optimizer 更新，不能代表完整训练峰值。若简单相加，超过 24576 MiB 约 175 MiB。
上述数值来自不同时刻，且 nvidia-smi 已用显存包含分配器缓存、预检指标只统计 PyTorch 已分配内存，因此不能据此断言并行必定失败；但它们说明单凭此刻剩余显存无法保证安全。后续训练输入、优化器状态、缓存和其他开销还会影响实际峰值。单卡并行还会争用算力，不能保证总耗时缩短。

队列语义：现有 supervise.py 顺序执行 BASE，然后在 BASE 成功完成 320 轮后自动启动 FULL；直接另启 FULL 将与既有队列发生重复启动或目录冲突。未经可靠的资源隔离和队列变更验证，不以在运行中的 BASE 为试验对象。

决定：维持已启动的单卡顺序队列，不更改 batch 4、FP32、seed 0 或 320 轮预算。若可提供第二张合适 GPU，可以另行检查设备、软件和数据一致性，再评估并行执行；若改变 batch 或精度，必须在两组之间保持可比并重新评估对既有 BASE 的影响。
