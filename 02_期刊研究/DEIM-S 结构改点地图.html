为什么是 160 / 80 / 40 / 20

没有任何数学原因要求是这几个数。它们只是 640 除以步长 4、8、16、32：Stem 里两次 stride 2 得到步长 4（C2），Stage2、3、4 开头各有一个 DW3/s2，所以每过一个阶段就减半。你猜的“都依赖上面那个”是对的：C5 是从 C4 算出来的，C4 又是从 C3 算出来的，粗层里的信息全部经过了细层。

这些数是可以改的：B0 配置里每个阶段都有一个 downsample 开关，编码器的 feat_strides、解码器的 num_levels 和 num_points 都是列表。真正决定小目标命运的不是 80 这个数，而是有效步长，也就是一个特征格在原图上覆盖多少像素。它等于网络步长乘以原图缩放倍数。

读源码时看到的五个结构事实

dfine_decoder.py · MSDeformableAttention

采样权重只看查询。attention_weights = Linear(query)，query 是内容加参考框位置编码。采样到的特征只被加权求和，从不参与决定权重。原生 B 和之前的 H 都在这个前提下，所以 H 无法纠正“按实际内容看选错了点或尺度”。

同上 · _reset_parameters / forward

采样点散布跟框走，不跟步长走。位置 = 中心 + offset·(1/n)·wh·0.5，初始化时 P3 三个点的半径是 wh/6、wh/3、wh/2，全在框内。整图里 5×7 px 的目标，P4 六个点、P5 三个点基本落在同一格的双线性插值上，读到的值几乎相同。

dfine_decoder.py · _generate_anchors

锚框先验偏大。边长 0.05·2^l，即 P3 32 px、P4 64 px、P5 128 px（640 尺度）。整图里的小目标只有 5 到 10 px。编码器头能学到修正量，影响可能不大，但先验与数据尺度分布不匹配是事实。

dfine_utils.py · bbox2distance / translate_gt

边分布的监督目标与框大小无关地“尖”。目标只落在相邻两格，1 个原图像素在归一化边距里等于 4/w。对 6 px 宽的框，1 px 标注误差就是 0.67 个单位，但目标分布仍按无噪声处理。LQE 又用这个分布的 top-4 概率估计质量。

configs · visdrone_detection.yml / deim.yml

评测上限和训练缩放需要核对。资料库 VisDrone 配置是 max_dets: 300，图册写 100，两者对 APs 影响可能不同。训练默认有 RandomZoomOut（再缩小最多 4 倍）和 SanitizeBoundingBoxes min_size 1，你们双视图训练用的是否相同，需要看实际配置。

候选改点

每个候选写清：动哪里、借的是哪个机器学习原理、可能为什么有效、先例情况、能在本机 CPU 上先做的判别检查、什么结果才值得上 GPU、什么结果就放弃。“机器学习换个名字”本身不是创新，能成为贡献的是：这个原理恰好对准你们测到的那个缺口，并且有简单对照替代不了的证据。

E0

先核对评测上限：每图最多计多少个框

先做判别 · 零推理
动哪里

不动网络。评测器的 max_dets，以及裁剪与合并结果是否按原图应用同一上限。

为什么先做

548 张验证图里有 26586 个小目标，平均每图仅小目标约 48.5 个。如果整图只计 100 个，而裁剪按窗口或更大的预算计，7 个点的差距里会混进一块与网络无关的数量效应。

CPU 检查

用已保存的预测，分别按 100 / 300 / 500 重算整图、裁剪、合并三组 AP，并统计真值超过 100 的图占多少。

怎么解读

APs 随上限明显变化：之后所有对比统一口径。几乎不变：数量效应可以排除，分辨率解释更站得住。

V2

跨视图特权信息蒸馏：让裁剪视图在训练时教整图视图

训练机制 · 推理零成本
机器学习原理

Vapnik 的“特权信息学习”（LUPI）：训练时能拿到、测试时拿不到的额外信息。Lopez-Paz 等人把它和知识蒸馏统一起来。这里的特权信息就是原分辨率裁剪。

动哪里

训练损失。同一真值在两个视图里各有一个匹配查询，用裁剪视图最后一层的边分布（映射到整图坐标、重新分格）作为整图查询边分布的软目标，再加分类分数蒸馏。D-FINE 自带的 DDF 层间蒸馏可以直接复用。

可能为什么有效

它直接对准测到的现象：同一权重，裁剪比整图强。如果整图特征里其实还有定位所需的信息，只是没被学出来，蒸馏能把裁剪的答案教给它。成功的话，推理时可以少用甚至不用裁剪，省掉 6.19 倍的观察成本。

先例

MSAD（CVPR 2021）做 CNN 检测器的跨分辨率特征蒸馏；ScaleKD（CVPR 2023）做尺度感知蒸馏；Semi-DETR 有跨视图查询一致性；D-FINE 有层间定位蒸馏。共享权重、DETR 集合匹配、边分布跨视图重分格这几点组合，我没查到直接先例，需要专门查新。

CPU 判别检查（关键）

“信息还在不在”探针：冻结第 81 轮权重，取约 100 张图里两个视图都检出的小目标，用整图最后一层查询特征（256 维）做岭回归，预测“裁剪框减整图框”的修正量。按图分成两半，交叉验证；用打乱配对作对照。

进入 GPU / 放弃

探针能解释可观比例的修正量，并让 IoU≥0.75 比例明显上升：值得做蒸馏。接近打乱对照：信息在整图特征里已经丢了，蒸馏没用，应转向 D2 这类补分辨率的结构。两种结果都有信息量。

D1

证据加权采样：MSDA 的权重同时看先验和采样内容

结构候选 · 解码器
机器学习原理

重要性采样与粒子滤波里的“先验提议 + 似然重加权”。现在的偏移量是提议，权重只来自先验（查询），从不乘似然。改成 w ∝ exp(zlp + λ·⟨Wqq, vlp⟩/√32)，λ 零初始化，起点与原生完全一致。

动哪里

MSDeformableAttention.forward：先采样得到 vlp，再算权重。每层加一个 256→256 投影，三层约 0.2M 参数，计算量相对全模型可忽略。需要走 PyTorch 采样路径，不能用原来的融合核。

可能为什么有效

整图里的小目标只占一格不到，查询事先不知道它在格内的确切位置。落在目标上的点和落在背景上的点读到的特征不同，现在这个差别被浪费了。它也是对 H 的根本修正：H 和原生都看不到内容。

先例

DAT（CVPR 2022，资料库有 DAttention.py）在骨干里对变形采样点做 q·k 注意力；Deformable DETR 原文为了效率选择只用查询；AdaMixer 的混合权重也来自查询。我没检索到在 DETR 解码器 MSDA 里用采样内容重算权重的直接先例，需要专门查新。

CPU 判别检查

内容相关性探针：冻结权重，对匹配小目标的查询收集全部采样点，标签为“点是否落在真值框内”。逻辑回归 A 只用 zlp（加尺度编号），B 再加采样值 vlp。按图划分留出集比较 AUC。

进入 GPU / 放弃

B 比 A 的 AUC 高出明显一截：内容里有权重没用上的信息，值得训练。几乎相同：前提不成立，放弃。训练对照至少要有“同样多参数但不看内容的权重头”。

D2

步长 4 只读值层：C2 只给解码器读，不进编码器

结构候选 · 解码器
动哪里

C2 经 1×1 投影到 256 维，作为 MSDA 的第 4 个 value 层，独立点集、独立 softmax，输出乘零初始化门后加回。不参与 Top-300 选择，不加检测头，不进 FPN。

可能为什么有效

上表说明整图视图里，小目标在 P3 上不到一格，唯一能提供不同读数的是更细的层。已有 P2 桥在编码器内部和输出端接入几乎没有差别（APs −0.028），说明编码器侧换位置不重要，剩下的问题是编码器侧还是解码器侧。

CPU 判别检查

采样散布诊断：对匹配小目标的查询，统计每个尺度上采样点的散布（以格为单位）和各点采样值的差异。若 P3 上小目标各点读数也几乎相同，D2 的前提成立。再加亚步长平移测试（窗口平移 0 到 7 px，看框是否随相位抖动）。

对照与放弃

同容量对照：输入换成“P3 上采样到步长 4”和“低通后的 C2”。增益落在种子标准差内，或低通 C2 与原 C2 一样好，就不能写成细节机制，只能作工程改进。

F1

定位分布的校准：小框的分布是否过度自信

监督与质量估计
机器学习原理

概率校准与含噪变量回归（errors-in-variables）。如果预测分布声称的不确定度和真实误差不符，LQE 拿这个分布估计质量就会排错序，而 AP 本质上是排序指标。

CPU 判别检查

冻结预测，按目标尺寸分箱：把每条边的分布换算成像素标准差，和实际误差比，看标准化误差的方差是否接近 1；再算每箱 LQE 质量分与真实 IoU 的 Spearman 相关。

可能的改法

小框明显过度自信或排序相关性明显更低时：按框大小给两格目标卷一个噪声核，σ = σ原图像素·reg_scale / w原图，零参数；或者给 LQE 加尺寸输入做重校准。

先例与放弃

KL-Loss（CVPR 2019）学习方差，GFL/DFL 用分布，NWD 改度量。若各尺寸箱校准都正常、排序相关性差别不大，就放弃这一支。

V1

视图分工：整图只管大于 s* 的目标，裁剪管更小的

协议 · 可先零训练验证
原理与先例

SNIP / SNIPER 的“有效尺度区间”：每个分辨率只对它擅长的尺度负责。原理是经典的，不算新；但它直接修你们已证实的合并问题：高分但定位差的整图框压掉更好的裁剪框。

CPU 检查

用已保存预测，按目标尺寸分箱比较两个视图的 AP，找到交叉点 s*；再按 s* 过滤后合并，看 AP 和 APs 的变化。零训练。

后续

有提升就把它定为新的强基线，之后所有结构对比都在这个协议下做。训练版本需要在匈牙利匹配和分类损失里处理“忽略区间”，这部分在 DETR 上有一点适配工作量。

定位

更像强基线而不是论文主贡献。但它决定了后面所有对比是否公平，所以排在前面。

Q1

查询预算：按尺度分配名额或动态 K

先例饱和 · 有条件才做
原理

分层抽样（每层保留配额）、行列式点过程式的多样化选择。

先例

DQ-DETR（动态查询数）、DDQ（去重的独特查询）、Dome-DETR（密度导向查询）都已存在；资料库里已有 dq_dfine_decoder.py 和 dqs_dfine_decoder.py 实现，可以直接当对照。

什么时候做

只有 E0 和查询数扫描（推理时取 300 / 600 / 900）显示查询预算贡献明显时才做。

放弃条件

K 从 300 到 900，APs 提升不到约 0.3，且小目标的提议召回已经很高。

D3

采样带宽下限：散布至少覆盖 κ 个格

与原对话候选重叠
原理

核密度估计的带宽选择：采样散布用 max(wh, κ·stridel)，零参数一行改动，保证粗层的点读到不同的值。

为什么不在这里推进

它和原对话负责的“采样范围 / 逐边半径”候选在同一个位置。按约定不干预那条线，这里只建议把它当成那条线的一个简单对照。“Better Sampling”（arXiv 2407.06127，VisDrone）也在约束采样点，方向相反。

B1

改金字塔本身：加 P2、去 P5、改下采样

先例饱和
机器学习视角

把金字塔层看成对“目标尺度”的量化器。Lloyd-Max 量化的结论是：量化级应该放在数据密度高的地方。VisDrone 的尺度集中在小端，现在的 8/16/32 把一级花在很少的大目标上，细端却没有级。

为什么不当主线

“加 P2 去 P5”在 VisDrone 的 YOLO 改进里非常普遍；UAV-DETR、Drone-DETR、HEGS-DETR 都把高分辨率层并入颈部；SPD-Conv、BlurPool、LIP 等下采样替换也都在资料库里。直接在 P2 上跑 256 通道的 RepNCSPELAN4，一个 3×3 卷积就约 30 GFLOPs，成本也不划算。

可以保留的用法

用尺度直方图把“为什么要补细层”量化出来，作为 D2 的问题依据，而不是作为新方法。

建议的顺序

  1. E0 评测上限，并核对双视图训练的实际缩放配置。零推理，决定以后用什么口径比较。
  2. V1 视图分工的零训练重合并。有提升就定为强基线。
  3. 两个探针一起做（都用冻结权重，在本机 CPU 上）：V2 的“信息还在不在”和 D1 的“内容相关性”。再加 F1 的校准统计。三者共用一次前向收集的数据。
  4. 按探针结果选路线。信息还在：V2 蒸馏优先，它推理零成本，论文故事最完整。信息已丢：D2 补细层优先。内容探针为正：D1 作为解码器结构贡献，可以与上面任一条叠加。
  5. 上 GPU 前先用至少 2 个基线种子估计标准差，事先写下筛选阈值，再各跑 1 个种子筛选；通过的才跑 3 个种子。

可以转给 DS 讨论的问题

1. DEIM-D-FINE-S 的 MSDA 权重只由查询线性生成，不看采样到的特征。如果改成“查询先验 + 采样内容似然”（权重 ∝ exp(z + λ·⟨Wq q, v⟩/√d)，λ 零初始化），在 DETR 解码器里有没有直接先例？最可能的反例是什么？

2. 用冻结权重做“内容相关性探针”（只用 z 预测点是否落在真值框内，对比加上采样值 v）能否作为 D1 的有效前提检验？有什么混杂因素会让 AUC 提升是假象？

3. 双视图共享权重训练时，用裁剪视图的边分布蒸馏整图视图（特权信息学习 LUPI），在 DETR 集合匹配和 D-FINE 边分布下，跨视图重分格应该怎么做才不引入偏差？

4. “整图查询特征能否线性预测裁剪视图的修正量”这个探针，能否区分“像素信息已丢失”与“信息还在但没学出来”？需要哪些对照？
