## 4 线程 C：Geo0 三分解（本轮新工作，L1，不跑前向）

v2 表里已经有一个没被解读的数：口径②覆盖只有 33.5% / 35.1%，也就是约三分之二的 Geo0 上，检测器没有任何一个同类预测落到 IoU≥0.1。这个数决定了后面所有方向，必须先拆开。

### 4.1 定义（写死，不许中途改）

对每个 Geo0 GT（分母 3715 / 3727），取其中心，考察半径 r = 8 / 16 / 32 px 三个窗口，统计：

- 窗口内 300 个 query 的个数（不看类别，看全部）
- 窗口内最高分类分数
- 该最高分 query 与 GT 的 IoU
- 该 query 是否能在后处理（分数阈值）后存活

### 4.2 三情形

- A 无 query：窗口内 query 数 = 0
- B 有 query 但分数被砍：最高分 < §0 第 5 问答出的阈值
- C 有 query 且分数够，但 IoU < 0.5：位置/尺寸不对

报 A / B / C 的占比，两个 seed 分开。判据：某一情形占比 ≥ 70% 才算"主导"；不足 70% 记 mixed，不许硬挑。

### 4.3 出口（每一种直接决定下一线程查什么）

- A 主导 → 采样密度问题。但密度 query / 动态分配类（Dome-DETR、PAQI、DQ-DETR、D3Q、MR-DETR）已在排除清单里，所以**这一条必须给出与它们可区分的机制**，给不出就写"无路径"，不许绕回"加 query"。
- B 主导 → 分类/排序问题：tiny 目标的分数量级被背景压住。
- C 主导 → 回归/分配问题，且要接着报 C 内部再分解：把匹配框的 w / cx / cy 分别替换成 GT 值，看 IoU 能否过 0.5（三个子替换 + 全替换，两 seed 分开）。这一步是 A 路径机制分析的核心数。

三条都必须给数，不许只给结论。
