## 3. Q1 判级：L2

### 3.1 依据

342_geometry_stage3_v2\geom342.py:170：

    valid=(cand_classes[:,None]==gt_labels[None,:])&(iou>=.5)

这一行同时生成 m0_legal_mask、并进而决定 m0_cand_owner 与 m0_gt_explained。也就是说，缓存里记录“这个 GT 被哪个 query 解释”的那条边，前置条件就是 IoU≥0.5。而 tiny Geo0 的定义正是 maxIoU<0.5。对这个 cohort，m0_gt_explained 恒为 False，不是“测出来没分配”，是**定义上不可能为真**。

实证（CODE\360_replay_tiny_geo0_probe.py → 360_replay_tiny_geo0_probe.json）：tiny_geo0_explained = 0/3715（seed1）、1/3727（seed2）。那 1 个是我用 FP32 复算 IoU 与原生 IoU 在 0.5 边界的差，不是真阳性。同脚本复现了 348 的全部口径数（n_gt 38759、tiny 4952、Geo0 3715/3727、pred_w_lt4 3145/2192），说明管线本身没错，错的是“重放能回答 Q1”这个假设。

### 3.2 为什么不能退一步用匈牙利重放 m0_cost_matrix

缓存里确有 m0_cost_matrix（300×N，5·L1＋2·分类项−2·GIoU，geom342.py:156-169）。但用它跑一次匈牙利得到“分配比例”，同样是构造性的：val548 平均 70.73 个 GT/图，只有 3 张图 GT 数超过 300（最大 317，p99=212）。只要 n_gt ≤ 300，匈牙利必然给每个 GT 各配一个 query，比例恒为 ~100%。这个数不区分任何东西。

再退一步，就算拿到真实训练时的分配，DETR 式匹配对每个 GT 都产出一个正样本框目标，所以“有 query”本身也不能证明该 GT 走进了有效的宽度回归——真正要看的量是**分配到的 query 有没有跑进 boxes 回归、以及回归目标可不可达**。这两件事都只存在于训练过程，不在缓存里。故 Q1 = L2。

### 3.3 L1 能给的部分

pred_w_lt4 3145/2192（1.9%/1.3%，348）与 3–4 px 下限属于 Q2 的旁证，不属于 Q1。Q1 的 L1 全部不可用。

## 4. Q2 判级：L2

### 4.1 依据

FDR 的宽度侧由两层张量决定（DEIM 本地源码）：

- engine\deim\dfine_decoder.py:465 pred_corners = bbox_head[i](output + output_detach) + pred_corners_undetach（4 边 ×(reg_max+1) bin 的 logits）
- engine\deim\dfine_decoder.py:466 inter_ref_bbox = distance2bbox(ref_points_initial, integral(pred_corners, project), reg_scale)，参考框来自第一层 pre_bboxes = F.sigmoid(pre_bbox_head(output) + inverse_sigmoid(ref_points_detach)) 并 detach（:460-462）
- engine\deim\dfine_utils.py:9 weighting_function：bin 值域对称，±upper_bound2，upper_bound2=|up[0]|·|reg_scale|·2
- engine\deim\dfine_utils.py:106-125 distance2bbox：x1 = points[...,0] - (0.5*reg_scale + d_l)*(points[...,2]/reg_scale)，x2 对称，故宽度 = pre_w·(1 + (d_r − d_l)/reg_scale)——**偏移有正负，宽度既能缩也能胀**，可表示边界是 d 落在 ±upper_bound2 端 bin。

这三样（pred_corners、pre_bboxes、ref_points_initial）都不在 342 缓存里。348:59 已写明：“342 val 缓存不含 encoder/decoder 中间层、pre/aux 输出、DN 和 query 层级信息”。缓存只有 final300 的成品框——那已经是 integral 之后的结果，拿不回来“分布是否顶边界”。

### 4.2 我算过的 L1 替代量，以及为什么它不能代替

用 final300 框按原图还原宽度，两 seed：

- 最小预测宽度 1.9917 px（seed1）/ 1.771 px（seed2），比 348 说的“3–4 px 下限”更低；
- 0–5 px 直方图（0.25 px 一格，seed1/seed2）：1.75:1/5、2.00:5/12、2.25:13/40、2.50:59/71、2.75:150/125、3.00:300/247、3.25:585/389、3.50:867/520、3.75:1165/783、4.00:1453/936、4.25:1575/1093、4.50:1844/1208、4.75:1902/1398。

单调上升，没有点质量、没有断崖、没有夹紧。所以“3–4 px 下限”是低概率尾部，不是 FDR 表示饱和。**这条只用来否掉“宽度下限＝顶边界”的偷换**，它不回答 Q2：没有 pred_corners 就没有“分布”。故 Q2 = L2。

## 5. “顶边界”的事前定义（在执行 L2 之前写定）

以下定义在拿到任何 Q2 数字之前固定，执行时不得改：

- 取与某 tiny Geo0 GT 关联的 query 在最后一层 FDR 的 4 组 logits，reshape 成 (4, reg_max+1)，侧序 [左, 上, 右, 下]。
- 对左、右两侧分别做 softmax，得 p_l、p_r（各 reg_max+1 维）。单侧顶边界质量 m = p[0] + p[reg_max]（两端 bin 的合计概率；均匀分布时约 2/(reg_max+1)≈6%）。
- 该 query 记为“顶边界”，若 max(m_l, m_r) ≥ 0.5。
- 统计量＝顶边界 query 数 ÷ 与 Geo0 GT 关联的 query 数，分 seed 报，并同时报 m 的中位数与 10/90 分位。
- 判据沿用 §3.2.2 的 30/10：≥30% 记“顶边界”；<10% 记“不顶”；10–30% 记 mixed→停。两 seed 方向不一致也记 mixed→停。
