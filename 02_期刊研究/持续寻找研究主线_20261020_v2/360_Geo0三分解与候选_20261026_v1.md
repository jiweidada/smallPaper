## 3 检出力自查（§3.2，红线 5）

### 3.1 换算（按实测，不按预设）

- **端点单位**：d 每 1 单位 = w_ref_px / reg_scale = w_ref_px / 4 的**单边位移**。实测 w_ref_px 中位 **5.3351 px（seed1）/ 5.6155 px（seed2）**，故 **1 单位 ≈ 1.33 / 1.40 px**，端点 ±4.0 = 每条边 ±5.3 / ±5.6 px。
- **中间 bin 宽**：project 的 33 个值中，内部相邻间隔恒为 **0.0760 单位 → 0.101 px（seed1）/ 0.107 px（seed2）**。v6 写的"≈0.3 px"不成立（那是按 16 px 参考框算的）。
- **端 bin 是跳变**：project 前三个值 = −4.000, −2.000, −1.788，末三个 = 1.788, 2.000, 4.000。从次端 bin 到端 bin 一次跳 **2.0 单位 = 2.67 / 2.81 px**。所以"顶格"不是渐变饱和，是掉进一个 2.67 px 宽的空洞——这使 P_top 对"表示饱和"的检出力本来就低。

### 3.2 可达区间：缩小方向没有地板（本轮新增的硬事实）

宽度公式 w_pred = w_ref ·（1 + (d_l + d_r)/4），d_l, d_r ∈ [−4, 4] ⇒ 因子 ∈ [−1, 3]，取非负宽度后**可达区间 = [0, 3·w_ref] = [0, 16.0 px]（seed1）/ [0, 16.8 px]（seed2）**。本 cohort 的 GT 宽度 p10/p50/p90 = **2.35 / 3.29 / 3.76 px**，完全落在区间内。

要点：这个模型**结构上不存在宽度地板**——两端的 corner 偏移可以从两侧各吃掉一半参考框，宽度可一路压到 0。所以"FDR 的 4 px 下限"不是表示层能给出的解释。

需要的收缩量：need = 4·(w_gt/w_ref − 1)，分位 p10/p50/p90 = **−2.43/−1.75/−0.93（seed1）**、**−2.51/−1.86/−1.08（seed2）**。零宽点是 −4.0，最极端可达 −8.0，即**中位需求只用了量程的 43.7% / 46.6%**。

### 3.3 P_top 降级

阳性条件是什么：只有当 need 逼近 −4（w_ref ≫ w_gt，参考框比 GT 大一个数量级）时，端 bin 才该堆积。本 cohort 的 need p90 只有 −0.93 / −1.08，**离端值还有 3–4 倍余量**。也就是说，即便模型完全正确、每条都精确回归到 GT，P_top 也应当接近 0。**P_top 低是统计量与本 cohort 的结构关系决定的，不是发现。**

故把 P_top 降级为：**"未观察到极端位移"**，不再用它支撑"表示层没有地板 / 没有饱和"。

"表示层没有地板"本轮只由以下三条支撑（各自独立、可复核）：
1. **E1 无 mod-4 量化**：project 33 个值非均匀但单调、内部间隔恒 0.076，不是 4 段周期结构（tmp\360_axisB_fdr_top_v2_ori2.json 的 project 字段有全量 33 值）。
2. **E2 无夹紧**：dfine_utils.py:106 distance2bbox 里 d 直接进线性式，无 clamp；代码路径上无 min-width。
3. **可达区间覆盖 0–5 px**：见 §3.2，[0, 16.0] ⊃ [2.35, 3.76]（p10–p90）；且实际预测宽度最小值 1.77 px（seed2），已低于 3–4 px。

### 3.4 检出力定量（这个检验能排除多大的效应）

口径② n = 1243 / 1307，事件数 0：

- 0 事件的 95% 单侧置信上限 = 1 − 0.05^(1/n) = **0.241% / 0.229%**。真实顶格率高于 0.24% 才会被这个样本量在 5% 水平上发现。
- 判据要求"有"的门槛是 30%，在 n = 1243 下需 **373 条**顶格（seed2 需 392 条）。实测 0 条。
- 若真实率为 10%，看到 0 条的概率 = 0.9^1243 ≈ **1e−57**；若为 30%，0.7^1243 ≈ 1e−444。
- **所以这个阴性不是样本量不足**：它对 ≥0.24% 的任何比例都有压倒性检出力，对"10–30%"量级的判定没有风险。它缺的检出力在另一头——对"表示饱和"这个特定机制，本 cohort 的 need 分布根本走不到端值（§3.3），**该检验与目标假设之间的量级差是 3–4 倍**（need p90 0.93 vs 端值 4.0）。

结论写死：**B-未顶**，且是"结构上不可能顶"的那一类未顶，不是"没观察到所以不确定"。

### 5.1 定义（写死，未改）

分母：tiny 且 maxIoU<0.5 的 GT，**3715（seed1）/ 3727（seed2）**（tiny 总数 4952，val548 共 38759 GT）。
对每个 Geo0 取中心，窗口 r = 8 / 16 / 32 px，窗内取**分类分数最高**的 query（不看类别），按三条判定：
- A 无 query（窗内 query 数 = 0）

## 6 四条交叉证据（支撑 §5 的出口判读）

1. **约三分之二的 Geo0 上，检测器一个同类框都没有落到 IoU≥0.1。** 任意类 IoU≥0.1 占 69.4% / 66.1%，同类只有 33.5% / 35.1% ⇒ **"有重叠但类别错"占 36.0% / 31.0%**（tmp\360_geo0_nest_v1.json）。这块之前没被算过。
2. **无口径②的 2472 / 2420 条不是"分配给了远处某个框"**：最近同类 query 中心距 p50 = 39.8 / 40.1 px（p25 18.0/17.8），best 同类 IoU 的 p90 = 0.0（九成恰好零重叠）；而**图内一个同类 query 都没有的只占 1.13% / 1.74%**。这些 GT 不是"没人管"，是"管它的框类别错了或位置差了 40 px"。
3. **重分配的理论上限就是 33.5% / 35.1%**。口径②已经是"同类里 IoU 最大"的选择，任何匹配代价/分配规则的改动，在**冻结预测**上都不可能有超过这个上限的收益。这条限死了"改匹配"类方法在 L1 上的空间。
4. Geo0 形状：短边 p50 2.82 px；w/h p50 **0.2368**，56.1% / 55.4% 的 w/h ≤ 0.25（细高）。GT-GT 嵌套（中心落在 ≥4× 面积的大 GT 内）只占 5.9%，同类嵌套 0.3% ⇒ **嵌套不是数据属性**；但预测侧嵌套占 10.1% / 10.7%（IoU p50 .143/.130，面积比 p50 6.2/6.9），说明模型自己会造出偏大的父框。
