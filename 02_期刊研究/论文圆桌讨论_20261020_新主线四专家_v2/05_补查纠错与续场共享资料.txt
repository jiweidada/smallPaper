# Claude · 原创性与反证｜第2轮

## 本轮回应对象

第1轮四人（包括我）都提出了同一个候选：固定的 `ref_points_initial` 与逐层更新的读取参考脱节。四人收敛于同一份 A5 资产，这本身就是一个风险信号。我本轮反驳的是三个具体表述：

- Codex C 的"上一层预测框重锚后可恢复可达性"；
- 我自己第1轮的"末层参考可达子集"。

## 致命的简单解释：读取位置本来就不可能越出写入支持

以下是条件推论，只针对当前工作副本的静态结构，未核历史 SHA。

1. 每层的 `inter_ref_bbox` 由 `distance2bbox(ref_points_initial, integral(累计pred_corners))` 解码得到。
2. 积分结果是 softmax 在有限 bin 上的加权和，所以各层预测框必然落在初始支持之内。
3. attention 的 `ref_points_detach` 就取自 `inter_ref_bbox`，因此读取位置同样被限制在初始支持内。

由此得出：读与写并非两个独立状态。"后层已经读到目标、只是写不出去"这种情形，最多只能发生在支持边界上。

这条结论给出一个比重锚更早、更便宜的致命检验：边界饱和检验。

- 检验对象：A5 中自身支持外的 1077/1223 个配对。
- 做法：用最终框相对初始参考反算每条边的偏移，看朝 GT 方向的那条边是否贴近支持上限（例如超过上限的 90%）。
- 如果多数配对贴边：说明范围约束在起作用，重锚才有讨论的必要。
- 如果多数配对停在支持内部：说明模型本身就没有往 GT 方向推，问题在于没读到目标或匹配身份错误。这时等宽平移（A）、分布迁移（C）、末层重锚（我）同时失效。

这项检验只需要初始框和最终框，不需要逐层 `inter_ref_bbox`，因此可能绕开第1轮各方担心的"逐层状态未落盘"这一缺口。前提是 A5 已保存这两个框，需要核实。

## 对各方的修订意见

我撤回自己第1轮的"末层参考可达比例 ≥15%"门槛。在上述结构下，它与饱和检验高度冗余，判定顺序应改为饱和检验在先。

对 Codex C："分布迁移并约束物理框一致"是重锚时避免坐标混用的工程必需步骤，不是贡献。此外它与 D-FINE 自身 GO-LSD 的关系没有人核过原文。我不接受把它列为可能的增量。

对 Codex A 的等宽平移支持：可以作为对照保留。但平移中心必须取模型自身贴边方向，不能取 GT。

对 Codex B：同意先核验能否把同一曝光、同一 GT、同一 query 连接起来。补充一点：饱和检验本身也受"最终配对反查"的选择偏差影响，需要同时报告未匹配 query 的贴边率作为基线。

## 收益上限必须先算

本候选的作用范围有限：

- 即使饱和检验通过，它也只覆盖"自身不可达"这一部分配对，而其中 551/680 个对全部 300 个 query 都不可达。
- A3 的 96% <4px 漏检属于 proposal 问题，A4 的全池覆盖仅比 TopK 多 +4.56/+6.08pp。

因此在投入任何训练前，应先写出上限：假设全部贴边配对的 IoU 都升到 .5，对小目标 APs 的最大影响是多少。如果上限低于 A1 中 C 的 seed 间波动（约 0.67pp），即使机制成立，也不值得作为主线。

## 已改变与仍存分歧

已改变的判断：我接受 Codex B 的意见，A5 不是训练轨迹，任何结论都只适用于冻结模型。

仍存的分歧：

- 我认为读写分离不是独立机制，三位 Codex 尚未回应这一点。
- 四人都没有提出 A5 以外的第二条数据触发。如果饱和检验失败，本场目前没有备选候选。我不在此替用户裁决是否继续。

- A5 是否保存初始框与最终框；
- `weighting_function` 的实际上限数值；
- D-FINE §4.1–4.2 是否讨论过支持饱和（我未读）。

第2轮 Codex A · 回归机制与代码
我回应Claude“第三个可恢复子集”的划分、Codex B“先核实同一曝光与query身份”的要求，以及Codex C“迁移保持物理框一致”的提案。我接受B的身份核查和C的简单重锚对照，但认为我们共同候选还缺一个更先行的检验：**精确GT框不可表达，是否真的限制了检测所需的IoU？**

已知A5有1077/1223个零IoU配对超出自身支持，但这不等于支持内不存在IoU≥.5的框。我因此修订首轮主张：对固定支持集合S，考察其可实现的最大IoU，而非仅检查能否精确重建GT。若多数失败配对的最大IoU仍超过评价阈值，有限支持就不能解释这些检测失败；不能再悄悄改称优化问题来保留原立项依据。

Claude的集合划分也需纠正：526/543个“别query可达”与551/680个“全query不可达”已经穷尽自身不可达配对。“自身后层参考可达”是另一条划分轴，可以与两组相交，并非第三个互斥子集。因此，全query初始不可达不能直接归为proposal问题，更不能借不同曝光协议的A3排除它。这项分歧尚未解决。

对C的迁移方案，我补充一个约束：若只是精确坐标变换，并保留全部物理支持，可达性不会增加；等宽移动支持则确实改变了可表达集合，旧分布可能被裁剪。保持解码框不变也弱于保持整个分布不变。这里可能有方法问题，但尚无创新证据。据共同材料转述，D-FINE已有固定参考分布精修；迭代重锚近邻仍待原文核查。

最低成本检验应先确认历史源码，再用已有配对和上一层预测框，比较固定支持、等宽平移支持与旧×2支持的最大IoU。新参考必须由模型确定；它只是读取位置的参考，不能证明已经读到目标。等宽平移改变位置，与×2不同，但旧负结果已提醒我们：解除几何限制并不足以保证收益。

最强反例是：固定支持本已容许合格框，或平移只扩大oracle可达性而没有可用目标信息。任一情况占主导，就停止“硬支持造成漏检”的候选。当前缺历史SHA、可连接的逐层参考及分布字段；齐全才值得做小表审计，缺失则本场只能保留未检验假设。
