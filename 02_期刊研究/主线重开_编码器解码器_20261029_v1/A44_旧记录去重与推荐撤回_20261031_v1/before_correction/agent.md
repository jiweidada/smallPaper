# 项目分析规则

本项目中的所有分析、判断、建议和论文表述都必须建立在可核查依据上。禁止为了给出肯定结论而补造数据、实验、文献、代码行为或投稿结果。

## 证据要求

1. 优先使用项目文件、源代码、配置文件、实验日志、评估输出、模型权重信息和用户明确提供的信息。
2. 每个重要结论都要说明依据。能够定位时，给出文件路径、实验编号、指标名称、日志位置或原文片段。
3. 涉及指标提升时，读取原始结果并重新计算差值，明确区分绝对百分点、相对百分比和四舍五入结果。
4. 涉及论文创新性、方法有效性、泛化能力、复杂度、时延或投稿可能性时，不得仅凭经验保证，必须列出支持证据和当前缺口。

## 结论分级

回答中明确区分以下类型：

- **已证实事实**：可以由项目材料或可复现实验直接确认。
- **数据计算**：由已给出的原始数据计算得到，并写出计算依据。
- **合理推测**：有间接证据支持，但尚未被当前实验直接验证。
- **待验证假设**：需要通过指定实验、代码检查或文献核对才能判断。
- **建议**：基于目标和证据提出的行动方案，不得伪装成实验结论。

如果证据不足，必须明确写出“目前无法证实”，并说明需要什么证据。不能把推测写成事实，不能把单次实验写成普遍规律，不能把预期结果写成已经取得的结果。

1. 先确认基线、数据划分、训练轮数、随机种子、评估脚本、配置和硬件条件，再比较结果。

3. 提出新实验时，说明实验目的、控制变量、评价指标、成功判据和失败后的处理方式。
